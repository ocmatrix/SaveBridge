# SaveBridge 今日上线方案（试运营）

> 本文只排顺序与分工，不替代手册；每个带【A/G】的动作都要负责人在对话里亲口授权，授权不外推。

## 0. 前提（已确认）

- 试运营，无灰度期；金库注资约 2–5 万 USDT（敞口上限）；额度取合约上限。
- 付款程序在 ss02，监控在 rpc3；本地加密钥匙文件，明日换 AWS KMS。
- 白名单钱包 0x8F36…F4A9、管理钱包 0x860f…5669（均为负责人硬件钱包）。
- 彩排：快进版本全绿；真实时间 rt5 并行复核，不阻塞上线，若 rt5 出红则按停止条件处理。

## 2. 执行顺序

1. **A1 只读/安装**：两台机器 `preflight` → `system` → `node` → `release`（不启动）。回退：删用户与目录。
2. **A2 生成钥匙**（负责人在场，亲自输入口令并离线保存）：ss02 三把（relayer-wantos、relayer-bsc、submitter）、rpc3 两把（pauser-wantos、pauser-bsc）；立即 `backup-keystore`，负责人试解一次。
3. **G1 部署者注资**（仅 gas）→ **G2 BSC 部署 / G3 WANTOS 部署**（用上面的地址授予角色，走时间锁的 48h 授权规则见手册 §3）→ 验收脚本 V1–V14 全过。
4. **A6 启动监控**（rpc3）→ 零一级告警 → 心跳演练：停监控，确认外部服务按时通知负责人，再启动。
5. **A6 启动付款程序**（ss02，此时白名单为空，不处理订单）→ `verify` → 心跳演练 → tunnel → 前端发布【G5】。
6. **A4 首批白名单**（白名单钱包在 admin 页签名，两条链各一次）→ **A5 注资**（先 2 万，跑稳再追加）→ 阶段 A 冒烟（小额一笔往返，手册 §10）。
7. 对外开放【G11】。

## 3. 每一步的验证与回退

| 阶段 | 验证 | 回退 |
|---|---|---|
| 安装 | `verify`：无新增非回环监听；邻居服务（nginx/coturn；节点/Blockscout/shim）状态与基线一致 | `systemctl disable --now`，删单元与用户 |
| 部署 | V1–V14；两链代理地址相同 | 未注资不动用，废弃该部署者 |
| 启动 | 零一级告警；心跳演练通过 | 停服务；暂停桥（负责人随时可做） |
| 注资后 | 冒烟一笔，三处一致 | 暂停 → 手册 §12 |

## 4. 停止条件（任一出现即暂停并停止推进）

未解释的暂停；一级告警不能在 5 分钟内说明原因；订单三处不一致；邻居服务（尤其 rpc3 节点块高）异常；监控与付款程序心跳任一丢失。

## 5. 上线前由总控只读核实（待 rpc3 访问）

V1 付款端经 `rpc3.wantos.io` 写入是否需要 `X-Wantos-Key`（普通通道 release 300 笔/秒，预计不需要）；V2 rpc3 本机 RPC 端口；V3 `pause()` 是否直连本机 8545；systemd 版本（Ubuntu 22.04 为 249 时凭据改存 root 0600 文件）；内存/磁盘余量。

## 6. 刻意不做的

- 不做灰度分级放量：试运营直接开放，敞口由注资量封顶；缓解：先注 2 万，稳定后追加。
- 不在上线日做 AWS KMS：明日换，换钥匙走 48h 时间锁，期间旧钥匙继续工作。
- 不加资金来源风控：风控只靠白名单。
