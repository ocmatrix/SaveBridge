## ① WANTOS-USDT（`0xc74F2e7fBdA2af9D1fc26b85E341229063Dc0873`）owner 权限审计

**方法**：读取链上运行时字节码，逐条解析 PUSH4 函数选择器，并检查代码区（排除末尾 51 字节元数据）是否含 `DELEGATECALL`、`SELFDESTRUCT`、`CREATE`、`CREATE2`、`ORIGIN`、`CALLCODE`。没有源码，也没有在浏览器验证；这是字节码层面的结论。

**合约不是代理**（升级槽为空），代码区共 4,454 字节。

**全部函数（13 个）**

| 选择器 | 函数 | 说明 |
|---|---|---|
| `06fdde03` `95d89b41` `313ce567` | `name()` `symbol()` `decimals()` | 只读 |
| `18160ddd` `70a08231` `dd62ed3e` | `totalSupply()` `balanceOf()` `allowance()` | 只读 |
| `a9059cbb` `23b872dd` `095ea7b3` | `transfer` `transferFrom` `approve` | 标准 ERC-20 |
| **`40c10f19`** | **`mint(address,uint256)`** | **增发**（owner 才能调用） |
| `8da5cb5b` `f2fde38b` `715018a6` | `owner()` `transferOwnership()` `renounceOwnership()` | 标准 Ownable |

**结论**
- **没有**：销毁（burn）、暂停（pause）、黑名单、冻结、强制转账、升级。代码区没有任何危险操作码。
- owner `0xc08187977f550f63b810da45b4ab8472f61df003` **唯一的特殊能力是增发**，以及转让或放弃所有权。
- 因此新桥里锁住的 WANTOS-USDT **不会被 owner 销毁或冻结**；风险只有"增发稀释"，由桥合约的 `supplyCeiling` 兜底（设计文档 §5.5）。
- **建议**：争取让 `0xc081` 持有者调用 `renounceOwnership()`；做不到的话，维持文档里的处置方式（增发只告警，超过上限后新的跨出被合约拒绝，负责人经时间锁提高上限）。

**待补**：如果能拿到该合约的源码或原始部署文件，可在浏览器做开源验证，并确认 `mint` 确实是 `onlyOwner`、没有额外的铸造上限。

## ⑤ EVM 版本

**WANTOS（chainId 13555）**，对 rpc3 做区块字段和操作码探测：

| 探测项 | 结果 |
|---|---|
| 区块头含 `baseFeePerGas`、`blobGasUsed`、`excessBlobGas`、`parentBeaconBlockRoot`、`requestsHash`、`withdrawalsRoot` | 有（Prague 级区块头） |
| `PUSH0`（Shanghai） | 通过 |
| `MCOPY`、`TSTORE/TLOAD`、`BLOBHASH`（Cancun） | 通过 |
| `BASEFEE` | 通过 |
| `BLOBBASEFEE` | **报错**（节点内部空指针）→ 合约**不得使用** |
| `CHAINID` | 0x34f3（13555） |
| `PREVRANDAO` | 返回全 `ff`，**不得依赖它做随机数** |
| 客户端 | Go 1.25.9，版本串为 `dev`（stock evmd） |

**BSC 主网**：`PUSH0`、`MCOPY`、`TSTORE`、`BLOBHASH` 均通过，`finalized` 区块可取，区块头含 `requestsHash`。

**结论**
- 两条链统一用 **`evm_version = "cancun"`** 编译，solc ≥ 0.8.24。
- 合约里**不使用 `BLOBBASEFEE` 和 `PREVRANDAO`**；不使用 `SELFDESTRUCT`。
- PR-1 的验收脚本要在两条链上再各自模拟一次实际部署（本次只做了操作码探测，没有部署）。
- 注意 gas 上限：WANTOS 区块 gasLimit 为 `0xffffffff`，不构成限制。

## ③ 钥匙仪式文档（初稿）

**要生成的钥匙**

| 钥匙 | 谁生成 | 在哪生成 | 保管 |
|---|---|---|---|
| 管理钱包 | 负责人本人 | 硬件钱包，离线 | 助记词抄写在金属板上，分两处保管，不拍照、不上传 |
| 白名单钱包 | 负责人本人 | **另一个**硬件钱包 | 同上，**与管理钱包分设备、分地点** |
| 部署者 EOA | 负责人或开发 | **干净的离线设备**，不经过任何旧工具 | 部署完成后销毁私钥 |
| 付款钥匙（两条链各一把） | KMS 内部生成 | 云 KMS | 私钥不出 KMS |
| 暂停钥匙（两条链各一把） | 服务器 B | 服务器 B 本机 | 只能暂停；定期轮换 |
| 提交服务热钥匙 | 服务器 A | 服务器 A 本机 | 只放 3 天 gas，无任何合约权限 |

**原则**
1. 任何人（包括开发方）不接触管理钱包和白名单钱包的助记词和私钥，只提供地址。
2. 助记词不进入任何联网设备、云盘、聊天记录和截图。
3. 生成后立即做一次"小额测试签名"，确认设备和备份可用。
4. 每季度演练一次：用备份恢复钱包并签一条测试消息，演练后确认旧设备仍可用。
5. 离职或人员变动时，通过合约的交接流程更换钥匙，而不是共享助记词。
